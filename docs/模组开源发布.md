## 二、发布说明（中文，可直接粘到 GitHub Release）

> **mchanhua 模组版 v0.1.0 —— 把 Minecraft 里的英文/日文变成中文**
>
> 挂在游戏的**文本 API**上直接取原始字符串（不是截图 OCR），交给 AI 翻译后就地替换或用右上角小窗对照显示。
> **纯客户端、不改存档**：只替换"画出来的那一份"文本，方块实体、实体数据、书里的内容一个字节都不动。
>
> ### 这个 Release 里有 4 个 jar，按你的游戏版本选一个
>
> | 文件 | 游戏版本 | 需要 Fabric API | 需要 Java |
> |---|---|---|---|
> | `mchanhua-26.1.2-0.1.0.jar` | 26.1.2 | 0.155.x+26.1.2 | 25 |
> | `mchanhua-legacy-1.21.8-0.1.0.jar` | 1.21.8 | 0.136.x+1.21.8 | 21 |
> | `mchanhua-legacy-1.21.1-0.1.0.jar` | 1.21.1 | 0.116.x+1.21.1 | 21 |
> | `mchanhua-legacy-1.20.1-0.1.0.jar` | 1.20.1 | 0.92.x+1.20.1 | 17 |
>
> **装错版本会在启动时报"模组注入失败"**（不同世代的游戏内部 API 不同），
> 请严格对应；每个版本都是独立适配并实测过的。
>
> ### 功能
>
> - 物品 tooltip 就地翻译（混排文本只翻英文行，游戏自带的中文属性行原样保留）
> - 聊天栏（只翻本地显示，不改服务器数据、不替玩家发言）
> - 标题 / 副标题 / ActionBar（地图台词常用；翻好再显示，不会先闪一句英文）
> - Boss 栏、告示牌、实体头顶名牌（玩家 ID 不翻）、世界里的悬浮大字、成书书页（按行翻，行数与分段不变）
> - 右上角 HUD 小窗：译文 + 原文对照，可自动收起
> - 游戏内设置界面（`K`）：填 API Key、选服务商与模型、开关各项功能、一键测试连通性
>
> ### 安装
>
> 1. 装对应版本的 Fabric Loader + Fabric API
> 2. jar 丢进该版本的 `mods/`
> 3. 进游戏按 `K`，把 API Key 粘进「API Key」框（默认打码，可点「显示」），点「测试一下」看到 ✓ 就通了
>
> ### 热键
>
> `H` 开关小窗 ｜ `J` 测试一次翻译 ｜ `K` 打开设置
>
> ### 支持的 AI
>
> 任何 OpenAI 兼容接口：DeepSeek（默认）、OpenAI、Kimi、通义千问、智谱 GLM、硅基流动、本地 Ollama（不用 key）。
> 设置界面里点「服务商」换家，会自动带上对应的接口地址与默认模型；列表里没有的点「手填」。
>
> ### 已知限制
>
> - **贴图里的字翻不了**：模组挂的是文本 API，图片里的文字它看不见——这种请用同仓库的桌面版（OCR）
> - 模组自己的 GUI（例如 FTB Quests 的任务书）没有通用挂点，需要按具体模组适配

## 三、Release notes (English, copy-paste)

> **mchanhua mod v0.1.0 — Minecraft text translation, in-game**
>
> Hooks Minecraft's **text APIs** (not screenshots/OCR) and translates the raw strings with an AI model,
> either in place or in a small HUD panel with the original text below.
> **Client-side only, and it never touches your save data** — only the text that is being drawn is replaced.
>
> ### Four jars in this release — pick the one matching your game version
>
> | File | Minecraft | Fabric API | Java |
> |---|---|---|---|
> | `mchanhua-26.1.2-0.1.0.jar` | 26.1.2 | 0.155.x+26.1.2 | 25 |
> | `mchanhua-legacy-1.21.8-0.1.0.jar` | 1.21.8 | 0.136.x+1.21.8 | 21 |
> | `mchanhua-legacy-1.21.1-0.1.0.jar` | 1.21.1 | 0.116.x+1.21.1 | 21 |
> | `mchanhua-legacy-1.20.1-0.1.0.jar` | 1.20.1 | 0.92.x+1.20.1 | 17 |
>
> Installing the wrong jar fails at startup with a mixin injection error — the internal APIs differ
> between generations, so each version is ported and tested separately.
>
> ### Features
>
> - Item tooltips translated in place (mixed tooltips: Chinese vanilla lines are left untouched)
> - Chat (local display only — server data is never modified and nothing is sent as the player)
> - Title / subtitle / action bar (common for map dialogue; held back until the translation is ready)
> - Boss bars, signs, entity name tags (player names skipped), floating text displays, written book pages
>   (translated line by line — line count and paragraph breaks are preserved)
> - HUD panel with translation + original, auto-hides
> - In-game settings screen (`K`): API key, provider/model pickers, feature toggles, one-click connectivity test
>
> ### Install
>
> 1. Install Fabric Loader + Fabric API for your game version
> 2. Drop the matching jar into `mods/`
> 3. Press `K` in game, paste your API key, hit the test button until it reports success
>
> ### Hotkeys
>
> `H` toggle HUD ｜ `J` test translation once ｜ `K` settings
>
> ### Supported providers
>
> Any OpenAI-compatible endpoint: DeepSeek (default), OpenAI, Moonshot/Kimi, Qwen (DashScope),
> Zhipu GLM, SiliconFlow, and local Ollama (no key needed).
>
> ### Known limitations
>
> - Text baked into **textures/images** cannot be translated (it is not text to the game) — use the
>   desktop OCR build in the same repository instead
> - GUIs drawn by other mods (e.g. FTB Quests) have no generic hook and need per-mod support

## 四、发布清单（照着做）

1. **推代码**
   ```
   cd D:\mchanhua
   git push origin main
   ```
   （或 GitHub Desktop 里点 Push origin）

2. **确认 4 个 jar 是最新的**（改过代码要重新 `.\gradlew.bat build` 再拷）
   ```
   D:\mchanhua\dist\mchanhua-26.1.2-0.1.0.jar
   D:\mchanhua\dist\mchanhua-legacy-1.21.8-0.1.0.jar
   D:\mchanhua\dist\mchanhua-legacy-1.21.1-0.1.0.jar
   D:\mchanhua\dist\mchanhua-legacy-1.20.1-0.1.0.jar
   ```
   > `dist/` 在 `.gitignore` 里：jar 走 Release 附件，**不要提交进仓库**（保持仓库轻）

3. **建 Release**：GitHub → Releases → Draft a new release
   - Tag：`mod-v0.1.0`（以后改模组就 `mod-v0.1.1`，与桌面版的 `v3.0.0`/`v4.0.0` 区分开）
   - Title：`mchanhua 模组版 v0.1.0（1.20.1 / 1.21.1 / 1.21.8 / 26.1.2）`
   - 说明：粘上面「二、发布说明」那一段
   - 附件：把 4 个 jar 拖进去

4. **仓库信息**：Description 与 Topics 见「一」

5. **（可选）给模组一条独立分支**：如果以后想单独发模组，可以
   ```
   git checkout -b mod
   git push -u origin mod
   ```
   但**不建议**：桌面版和模组共用同一套“每次改动补测试”的约定，分仓会让版本记录割裂。

## 五、以后怎么维护（省事版）

- **只在改代码后重建**：四个工程各自 `.\gradlew.bat build`，构建完把 `build\libs\*.jar` 复制到 `dist\`
- **发布粒度**：一次改动 → 一个 tag（`mod-v0.1.x`）→ 一个 Release（4 个附件）
- **改一个功能要四个工程同步改**：核心文件（`TextLines` / `TranslationService` / `TranslationCache` /
  `ConfigDraft` 等）是复制关系，改完记得逐个同步并各自跑构建
- **升级思路**：老版本线之间多数是"改几处签名"（例如 1.20.5 改 tooltip 参数、1.21.2 把实体渲染
  改成状态驱动）；新增版本先拉 Yarn 映射确认挂点存在，再建工程
- **不要提交**：`dist/`、`build/`、`run/`（含 API Key 与存档）、`*.local.toml`

## 六、测试（OpenSource 时给用户的信心）

每个工程都自带纯逻辑自测，**不进游戏、不联网**：

```bash
cd mod        # 或 mod-1.21.8 / mod-legacy / mod-1.20.1
./gradlew.bat build
```

会跑三套：`hudtest`（HUD 折行/截断）、`configtest`（配置兜底与解析）、
`translatetest`（回放防重入、按行翻译、缓存行为），四个工程合计 214 项断言，全绿才算通过。

# 同类开源项目调研与借鉴

2026-09-29 在 GitHub 上调研了与 mchanhua（游戏屏幕取词翻译）功能相近的项目，记录可借鉴的做法与取舍。

## 调研对象

- SethRobinson/UGTLive（C#）：实时屏幕翻译，26 种语言，LLM + GPU OCR，游戏/漫画/PDF
- bnsware/SubLens（Python）：Windows 游戏对话翻译，Tesseract OCR + 可拖动悬浮层
- ciddwd/overlay-translator（Kotlin）：Android 屏幕实时翻译，端侧/云 OCR + 覆盖显示 + TTS
- Hon-Lu/OverTranslate（C#）：Windows 屏幕翻译（日常/漫画/影音/游戏）
- TAKU-ZE/screenshot-translator（Python）：热键捕获区域 → OCR → 翻译 → 覆盖回选区

## 已经借鉴并落地的

1. **等画面稳定再翻译（settle）** —— UGTLive 的卖点是"detects changes and translates when things settle"。
   游戏里的提示框是淡入的，抓早了只能翻到半截。现在抓屏会连抓两帧比较（缩到 64×36 比灰度差，几十微秒），
   不一致就再等 0.12 秒抓第三帧。默认 `ocr.settle_frames = 2`，实测多花约 145 ms（OCR 本身 700 ms+）。
2. **网络抖动自动重试** —— 同类工具普遍会重试。连接失败/超时这类可恢复错误现在自动重试
   （0.6 s、1.2 s 退避，共 3 次尝试），服务端返回 4xx/5xx 不重试。以前网络一抖就直接报错，等于白按一次热键。
3. **翻译缓存** —— SubLens 用 200 条 LRU；我们用 sqlite 持久缓存（模型 + 提示词版本 + 原文 做哈希），更省。
4. **术语表** —— SubLens / UGTLive 都有 glossary 保护专有名词；我们已有 `[glossary]` 配置。
5. **全局热键 + 可自定义** —— 两家都有；我们已支持自定义与"选择按键"录制。
6. **选区取词** —— 都提供"框一块区域 + 热键翻译"；我们额外做了选区外扩、整行完整性与"选区内没文字就提示"。

## 暂未采用（记录备选）

- **连续扫描 / 变化检测**：每 0.5~15 秒自动翻一次（SubLens、UGTLive）。我们定位是"按热键才翻"，不做常驻抓屏，省 CPU 也省 API。
- **失焦自动暂停**：只有连续扫描才需要。
- **OCR 预处理与自动挑选最佳模式**（SubLens 的 6 种预处理 + Otsu + 2/3/4 倍放大）：我们目前只开放 upscale / invert。
- **点击穿透覆盖层**：UGTLive 的 Passthrough；我们是独立小窗，不需要。
- **系统托盘、开机自启、TTS 朗读、自动更新**：产品化功能，需要时再加。

# mchanhua v2 总览（存档）

存档时间：2026-09-27。打包成 app 之前的最后一个版本。

## 定位没变

自己玩游戏时看懂英文：**屏幕取词 → 翻译 → 小窗显示**。不改游戏文件、不注入进程。

## v2 新增（相对 v1）

| 需求 | 实现 |
|---|---|
| 取词用自定义选区 | 选区保存在 `config.local.toml` 的 `[regions.fixed] custom`，重启仍生效 |
| `Alt+/` 框选并立即翻译 | 弹出框选 → 松开就翻译这一次的区域，**不覆盖**已保存的选区 |
| `Alt+M` 全屏翻译 | 整屏识别 + 翻译，行数上限 60，译文区带滚动条 |
| 选区与翻译联动 | `Alt+V` 只框选并保存；`Ctrl+Alt` 翻译该选区 |

## v2 期间修掉的坑（都很关键，v3 别重犯）

1. **消息队列自喂**：drain 执行任务时又往同一队列放消息 → 主线程死循环、窗口"未响应"。
2. **sqlite 跨线程**：连接在 A 线程创建、B 线程使用会直接报错 → 现在 `check_same_thread=False` + 锁。
3. **"翻译不全"**：选区把句子切断，OCR 只看得到半句。现在改成**整屏识别 + 按选区筛选**
   （只保留中心点在选区内或与选区重叠 ≥25% 的行），行必然完整。
   对比实测：旧 `Tou are one step aloser to 3` → 新 `Tou are one step closer to saluation but your destiny lies in`。
4. **热键要按两次**：`keyboard` 库要求"当前按下的键集合恰好等于热键"，
   选区弹窗丢掉一次 key-up 就残留按键 → 现在所有热键都用自家匹配（组合键都按着即触发）。
5. **繁忙丢请求**：翻译期间（约 2.5 秒）再按热键会被丢弃 → 现在记下最后一次请求，结束后自动执行。
6. **配置写错位置**：`save_config()` 默认写 `%APPDATA%`，与 `load_config()` 不一致 → 现在统一解析顺序。
7. **热键符号**：字符类里的 `-` 意外形成范围，导致 `alt+/` 非法 → 逐字符转义。

## 打包前的准备（本次一并提交）

- **多 AI 服务支持**：`OpenAICompatibleTranslator` + 服务预设（DeepSeek / OpenAI / Kimi / 通义 /
  智谱 / 硅基流动 / Ollama 本地 / 自定义），只需换接口地址与模型名。
- **界面外置**：颜色、字体、字号、内边距、透明度、窗口尺寸全部来自配置
  （`config.toml` 的 `[ui]` 段），改 UI 不用动逻辑代码。

## 热键一览（可在配置里改）

| 热键 | 作用 |
|---|---|
| `alt+v` | 只框选并保存选区 |
| `ctrl+alt` | 翻译已保存的选区 |
| `alt+/` | 框选并立即翻译（不保存） |
| `alt+m` | 全屏翻译 |
| `alt+s` | 翻译剪贴板里的图片 |
| `ctrl+alt+x` | 退出 |

# 模组多版本支持：现状与踩坑记录

## 已经就绪的东西

- **Stonecutter 0.9.8** 已接入：`settings.gradle` 里 `shared { versions ... }` 定义版本树，每条线自己的
  版本号放 `versions/<mc>/gradle.properties`，`vcsVersion` 决定不带前缀的任务走哪条线（现在是 26.1.2）。
  - 构建：`.\gradlew.bat build`（走 26.1.2）/ `.\gradlew.bat :26.1.2:build`
  - 跑游戏：`.\gradlew.bat :<版本>:runClient`，工作目录在 `versions/<版本>/run/`
  - jar 命名：`mchanhua-<mc版本>-<mod版本>.jar`，一眼看出给哪个游戏版本
- **JDK**：本机已装 25（26.x 用）与 21（Temurin 21.0.12.1，放 `D:\Tools\jdk-21`，1.21.x 用），
  路径登记在 `gradle.properties` 的 `org.gradle.java.installations.paths`。

## 各条线需要的版本号（查过 Fabric 官方源）

| 线 | minecraft | fabric-loader | fabric-api | 编译用 Java |
|---|---|---|---|---|
| 26.x | 26.1.2 | 0.19.5 | 0.155.3+26.1.2 | 25 |
| 1.21.x | 1.21.1 | 0.19.5 | 0.116.17+1.21.1 | 21 |
| 1.20.x | 1.20.1 | 0.19.5 | 0.92.12+1.20.1 | 17 |

## 两个必须先解决的坎（1.21.1 实测撞到）

1. **Loom 版本不通用**。26.x 用的 Loom 1.18 在处理 1.21.1 的 Fabric API 时直接报错：
   ```
   Failed to process jar ... fabric-loom:access-widener
   Expected official namespace for access widener entry, found: intermediary in mod: fabric-biome-api-v1
   ```
   原因是 1.21.x 时代的 Fabric API 的 access widener 是 **intermediary** 命名空间，而 Loom 1.18 按
   **official** 处理。老线要用**当年的 Loom**（每条线一套），需要把插件在各节点上分别 apply，
   而不是只在根 `build.gradle` 里声明一次。

   **后续实测补充（重要）**：
   - Loom 1.14.1（新版 id 里最老的一个）**同样报这个错**，说明"官方映射 + intermediary AW"这条路
     在 1.14+ 都走不通。
   - 插件 id 分两段：新 id `net.fabricmc.fabric-loom` 只覆盖 **Loom 1.14+**；
     Yarn 时代（Loom 1.13 及以前）用的是旧 id **`fabric-loom`**（插件门户能解析）。
   - 所以路线是：**每条线一份构建脚本**，靠 Stonecutter 的 branch 机制分开——
     `modern` 分支（26.x）用新 id + Loom 1.18；`legacy` 分支（1.21.x/1.20.x）用旧 id + 当年的 Loom + Yarn 映射。
     公共部分抽成 `gradle/common.gradle` 给两边 apply。
   - 还没验证的一环：**旧 Loom（1.11~1.13）能不能在 Gradle 9.7.1 上跑**。
     如果不兼容，legacy 线要么单独用一个 Gradle wrapper，要么单独开一个工程。这一步要优先验证。

   **已解决（实测通过）**：
   - 旧 Loom **1.13.6**（旧 id `fabric-loom`，发布在 maven.fabricmc.net）在 **Gradle 9.7.1 上配置正常**，
     1.21.1 + Yarn + Fabric API 0.116.17 的 access widener 报错消失。
   - 两条线可以共存：`:26.1.2`（新 id + Loom 1.18.2 + 官方映射）与 `:1.21.1`（旧 id + Loom 1.13.6 + Yarn）。
   - 做法写在 `settings.gradle` 里：扁平版本列表，节点用 `vers(...).buildscript('build-legacy.gradle')` 指定脚本；
     公共配置在 `gradle/common.gradle`，Java 版本、映射、Loom 版本都来自各节点的 `gradle.properties`。
   - **启用 1.21.1 前必须先把版本层改写成 Yarn**，否则它会编译失败，而根 `build` 会聚合所有节点，
     一挂上去 `gradlew build` 就红（移植期间该行保持注释）。
- 第一份 Yarn 改写清单（编译报错直接给出）：`net.minecraft.resources` → `net.minecraft.util`
  （`Identifier` 在 Yarn 下是 `net.minecraft.util.Identifier`），后续按报错逐个替换。
2. **命名空间不同：这是最贵的部分**。我们的代码是照 **Mojang 官方映射**写的（26.x 已不再发布 Yarn），
   而 1.21.x 生态是 **Yarn**：

   | 我们现在的名字（official） | 1.21.x 的 Yarn 名字 |
   |---|---|
   | `Minecraft` | `MinecraftClient` |
   | `GuiGraphics` / `GuiGraphicsExtractor` | `DrawContext` |
   | `ChatComponent` | `ChatHud` |
   | `Gui` | `InGameHud` |
   | `Button` / `EditBox` | `ButtonWidget` / `TextFieldWidget` |

   核心翻译逻辑（缓存、队列、按行挑选、提示词、配置、7 个自测）**完全不碰这些名字**，可以原样复用；
   要重写的是"版本层"：约 8 个类 + 11 个 mixin。

## 建议的推进方式（一次只加一条线）

1. 1.21.1：各节点单独 apply 当年的 Loom + Yarn 映射，把版本层用 Yarn 名字写一遍（成功后 1.20.1 / 1.18.2
   基本可复用同一套 Yarn 名字）。
2. 1.20.1：同上，注意 Java 17 与 Fabric API 0.92.x。
3. 1.16.5：最后做，额外要把核心代码降到 Java 8 语法（实测 2 处文本块 / 66 处 `List.of` /
   13 处 `strip()`~`isBlank()`），并且渲染入口全变（没有 `GuiGraphics`）。

1.6~1.15 不在范围：那时候没有 Fabric（1.6/1.7 连 Mixin 都没有），交给桌面版 OCR 覆盖。

## 加节点时别踩的坑

- **删掉坏节点再提交**：只要 `shared { versions ... }` 里有一个节点配置失败，`gradlew build`
  就会整体失败（Gradle 会配置所有项目）。
